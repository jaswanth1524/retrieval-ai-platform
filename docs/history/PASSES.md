# Implementation notes, pass by pass

The detailed record of what each pass built, measured and decided: names of the functions
and settings involved, the reasons behind non-obvious choices, and what was measured and
not shipped. It used to be the "Current State" section of `CLAUDE.md`; it moved here in
pass 19 so the agent guide stays short. Read the entries for a module before changing it —
many of them explain why code that looks redundant is there.

Later passes add their notes at the end. Names in older entries may have moved since (a
later entry says so where it happened).

- Core upload, ingestion, hybrid retrieval, reranking, streaming Q&A, citations, and per-query debug traces (`GET /traces`) are implemented (`api/`, `frontend/`).
- Session-scoped multi-file upload, per-document search-scope filtering, document deletion (`DELETE /documents/{filename}`), client-sent conversation memory with LLM-condensed follow-up retrieval, chat UX (markdown rendering, persistence, export, retry, responsive layout), and ops/quality hardening (`/health/ready`, eval-dataset CI validation, Docker healthcheck/non-root) are implemented and merged to `main`.
- Optional single shared API key (`AppSettings.api_key`, empty by default): when set, every `/documents*` route (list, upload, delete, `/content`, `/original`, `/jobs/{job_id}`, `/reindex`, `/tags`), `/questions*`, `/search`, `/traces*`, `/feedback`, `/export`, `/import`, `/access`, and `/metrics` require a matching `X-API-Key` header (`api/dependencies.py:require_api_key`); only `/health`, `/health/ready`, and `/config` stay open (the OpenAPI docs are guarded too), so healthchecks, probes, and the UI's boot request keep working. A Prometheus scraper needs the header in its scrape config. The corpus *read* routes are guarded deliberately — an open `GET /documents` enumerates filenames, `GET /documents/{filename}/content` returns raw chunk text, `GET /documents/{filename}/original` returns the raw uploaded bytes (opt-in, see `raw_document_dir` below), and the job-status response carries the filename — so leaving them open would protect Q&A while the documents stayed readable. The comparison is on **bytes**, not `str`: `secrets.compare_digest` raises `TypeError` on a non-ASCII `str` and Starlette hands headers over latin-1-decoded, so a str comparison turned any non-ASCII `X-API-Key` into an unauthenticated 500. Not multi-user auth.
- Original uploaded bytes are discarded once ingestion is queued unless `AppSettings.raw_document_dir` is set (empty by default — off), in which case `api/raw_documents.py:RawDocumentStore` keeps a copy on disk keyed by the same normalized basename filename ingestion uses, and `GET /documents/{filename}/original` serves it back. `DELETE /documents/{filename}` removes the stored original under the same `filename_write_lock` ingestion/delete already share. `POST /documents/{filename}/reindex` (202 + job id, same backlog/job/executor path as upload via `api/ingest_jobs.py:enqueue_ingest`) re-chunks and re-embeds a document from its stored original, keeping its `uploaded_at` and passing no raw store to the job (a failed re-save would delete the only copy); 409 when `raw_document_dir` is unset, 404 when that document has no original. `POST /documents/reindex` does the same for every *stale* document with an original, returning the accepted jobs plus any `deferred` when the backlog fills. Every chunk payload carries `chunker_version`; `repository.filename_metadata` takes the **minimum** per filename (missing = legacy = stale, and a partial re-ingest can leave old-version points), and `GET /documents` returns `stale_filenames` and `reindexable_filenames`. `PublicConfigResponse.raw_documents_enabled` gates the corpus panel's ↻ button, and a card is labelled "older chunking" only when it is re-indexable (a legacy card with no original would carry a label the user can't clear). Staleness is `DocumentMetadata.is_stale` (`api/repository.py`), shared by `GET /documents` and `POST /documents/reindex`: a document is stale when any point predates `CHUNKER_VERSION` (or carries none), when any point's `chunking_fingerprint` (`documents.chunking_fingerprint`: chunk size, overlap, min section words, CSV rows, dense model, chunker version) differs from the current one, or when the heuristic token counter sized it while the HF tokenizer is available now (`token_counter` payload). A point with no fingerprint but a current version counts as current, so an upgrade doesn't flag the whole corpus.
- Answer feedback (thumbs up/down, `ChatMessage.tsx`) is off by default (`AppSettings.feedback_enabled`); when on, `POST /feedback` writes to `api/feedback.py:FeedbackStore` — its own sqlite3 file (`feedback_store_path`), independent of `job_store_backend` below, so it works whether or not that's set to sqlite. Rows are denormalized (question, answer excerpt, cited filenames alongside `trace_id`) rather than joined through `trace_id`, since `TraceStore`'s ring buffer can evict a trace before the row is ever read back. `PublicConfigResponse.feedback_enabled` tells the frontend whether to render the buttons; both `POST /feedback` and `GET /feedback` 404 when the feature is off. `GET /feedback?limit=` (newest first, `limit` bounded by `FEEDBACK_LIST_MAX_LIMIT`) is the read side — without it captured ratings would be reachable only by opening the sqlite file by hand, which defeats the point of capturing them.
- A per-filename write lock (`api/ingestion.py:filename_write_lock`, a context manager) serializes every read-modify-write of one filename's points. Both `ingest_chunks` and `DELETE /documents/{filename}` take it — each is a snapshot-then-mutate, so guarding only the ingest path still let a delete landing mid-ingest remove points that ingest had just written while the ingest reported success. Registry entries are reference-counted and evicted when the last holder releases, so it tracks in-flight work rather than every filename the process has ever seen.
- `reranker_batch_size` (default 8) bounds the cross-encoder's peak memory and must stay `<= rerank_candidates`; above that, batching is a no-op and every pair is scored in one forward pass. The old default of 64 against 50 candidates peaked at 6.33 GB and OOM-killed the container (exit 137) on the first whole-corpus question. At 8 the peak (fp32) is 2.66 GB — equal to the loaded-model baseline (the default int8 model peaks around 1.4 GB), so scoring adds nothing and the boot-time warmup already reaches the true high-water mark. Latency is flat across batch sizes, so this costs neither speed nor answer quality. Docker needs ~4 GB.
- Retrieval-quality pack: token-aware sentence-boundary chunking (`api/chunking.py` counts the dense model's real subword tokens; `chunk_size_tokens`/`chunk_overlap_tokens` are now genuine tokens), query/corpus embedding symmetry (bge dense query instruction + BM25 `query_embed` in `api/embeddings.py`), post-rerank near-duplicate diversity filter (`api/diversity.py`, trace drop-reason `near_duplicate`), opt-in multi-query expansion (`QUERY_EXPANSION_ENABLED`, default off — cross-variant fusion reuses the same pinned `rrf_k`), and a zero-citation retry (`CITATION_RETRY_ENABLED`, default on). The chunking change does **not** bump `embedding_model_tag` (same vector space; re-upload recommended, not required).
- Format expansion (`api/documents.py`): DOCX/HTML/CSV parsers, PDF table extraction (pdfplumber), and optional OCR for scanned PDFs (`rapidocr-onnxruntime`, `ocr` extra). Frontend product pack: multi-conversation chat (localStorage v2 with v1 migration in `useChat.ts`), chunk-based source viewer + citation click-through (`GET /documents/{filename}/content`, `DocumentViewer.tsx`, windowed around the cited chunk for large documents), trace-history browser (`TracesPanel.tsx`), and unified whole-corpus search-scope filtering. Application logging is wired via `LOG_LEVEL` (`api/logging_config.py`).
- `GET /documents` also returns `page_counts`/`byte_sizes`/`uploaded_ats` per filename (`api/repository.py:filename_metadata`, one scroll, folded together — not a query per field), rendered in `CorpusPanel.tsx`'s card detail line. `byte_size`/`uploaded_at` come from `api/documents.py:DocumentChunk`, stamped once per upload in `IngestService.ingest` (`api/pipeline.py`) and so absent (not null) for any document indexed before this shipped. `ChatMessage.tsx` also offers Regenerate (re-asks the nearest preceding user turn's question, found by array position in `ChatThread.tsx`) on a successful answer, and both `CorpusPanel.tsx` and the composer's scope popover (`Composer.tsx`) filter their document lists by a substring match — the popover always keeps an already-selected filename visible regardless of match, since the checkbox list is the only way to unselect it.
- Evaluation (`eval/ragas_runner.py`, sample at `eval/datasets/sample_eval.jsonl`) plus a live retrieval/answer harness (`eval/harness.py`, `eval/metrics.py`, labeled sample `eval/datasets/retrieval_eval.sample.jsonl`, baselines under `eval/baselines/`). The harness logic is unit-tested with fakes, and CI's `qdrant` job runs the handbook set for real against its baseline. Both test suites (`tests/`, `frontend/tests/`) run in CI (`.github/workflows/ci.yml`), which also builds the Docker image.
- Latency/robustness pass (measured on an M1 + Docker, see README "Latency"): Ollama is called via LiteLLM's `ollama_chat/` route — the `ollama/` (`/api/generate`) route filed `keep_alive` under `options`, where Ollama rejects it, so the model unloaded after 5 minutes regardless of `OLLAMA_KEEP_ALIVE`; optional `OLLAMA_NUM_CTX` (0 = Ollama's choice). `supports_reasoning` never consults LiteLLM for Ollama models (it did an uncached `/api/show` to the wrong host — 75s per call when unreachable). The generation prompt omits `chunk_id` (citations still carry it via structured `sources`) and tells the model not to append a references list; `expand_with_neighbors` expands only the `max_context_chunks` prefix, never re-sends a chunk that has its own block or already appeared, and trims chunk overlap at consecutive joins. A zero-citation retry on the stream path is announced with a `verifying_citations` stage frame. LiteLLM reports a request timeout as `APIConnectionError`; `generation.py` now says "timed out after LLM_REQUEST_TIMEOUT_SECONDS" instead of "Cannot reach Ollama". The reranker serializes forward passes (OOM guard), memoizes scores per (query, passage) (`RERANK_CACHE_SIZE`), and loads jina's int8 export by default (`RERANKER_ONNX_FILE=auto`; alternate exports get their own fastembed cache dir, since a cached fp32 snapshot made fastembed skip downloading them); `EMBEDDING_THREADS`/`RERANKER_THREADS` cap ORT threads (0 = default). Query embedding has its own executor so questions don't queue behind ingest batches; a rejected server-side hybrid query is remembered per client.
- Ingestion hardening: `POST /documents` validates filename/type before the 202 (400 for unsupported types, `.`/`..`, control characters) and admits uploads against a byte budget (`INGEST_MAX_PENDING_BYTES`, 503 + `Retry-After` past it). The raw original is saved only after indexing succeeds, atomically, under the filename lock (`ingest_chunks(on_indexed=...)`); `DELETE` also removes an original with no points; `/original` is a `FileResponse` (streams, RFC 5987 filenames, `nosniff`). The sqlite job store runs in WAL mode and fails jobs a restart interrupted. Token counts exclude special tokens (reserved once per chunk via `special_tokens_per_sequence`) — `CHUNKER_VERSION` 3, no `embedding_model_tag` bump, re-upload recommended. PDFs: the table finder is skipped on pages without ruling edges, and empty pages are OCR'd even in mixed PDFs. Docker keeps models in a `model_cache` volume (`FASTEMBED_CACHE_PATH`/`HF_HOME` under `/home/app/.cache`) and precompiles bytecode.
- Review follow-up pass (after PR #10/#11):
  - LLM errors: a real `litellm.Timeout` (OpenAI raises it bare; Ollama wraps it in `APIConnectionError`) now reads as "did not finish within LLM_REQUEST_TIMEOUT_SECONDS", while an httpx `ConnectTimeout` anywhere in the exception chain (unroutable host) still reads as "Cannot reach Ollama" (`llm.py:_is_request_timeout`).
  - Ingest ordering: `on_indexed` (store the original) runs before stale-chunk cleanup, so a failed cleanup can't leave `/original` serving the previous version. Neighbour-overlap trimming takes the *shortest* match, capped near `chunk_overlap_tokens`, and does nothing when overlap is 0, so repeated rows aren't dropped.
  - OCR failure handling: OCR failures on one page, or of the whole engine, no longer fail a mixed PDF.
  - Uploads rejected with a 400: a DOCX whose zip members expand past `DOCX_MAX_EXPANDED_BYTES`.
  - Uploads rejected with a 503 (and the job marked failed): an upload arriving while the ingest executor is shut down.
  - Shutdown: the lifespan exit shuts the ingest pool down (queued jobs cancelled and failed, running ones finish) and clears its cache. The embedding pools are deliberately left running, because a running ingest still embeds through them.
  - Security: answers never load markdown images (`ChatMessage.tsx` renders their alt text), and the system prompt says source text is data, not instructions.
  - Metrics: `docrag_ingest_job_seconds{outcome}` histogram.
  - Caching: the `/config` Ollama probe is cached ~10s per base URL (`provider_health.check_ollama_reachable_cached`).
  - Infra: Qdrant pinned to `v1.19.1` in compose. CI audits runtime deps (`pip-audit` on core+`ocr`+`mcp`, `npm audit --omit=dev`). Dependencies, action SHAs and base-image digests are bumped by hand (no Dependabot config).
  - Frontend:
    - Dialogs and the inspector are `React.lazy` chunks (react split out in `vite.config.ts`) behind `LazyChunkBoundary`, which turns a missing chunk from a stale tab into a "reload" prompt instead of a blank app.
    - Below 860px the context panel is a drawer toggled from the rail, and below 1120px the inspector opens as a drawer. Both use `useDialog`, which keeps a stack so only the innermost dialog handles Escape and Tab.

- Full review pass (after PR #12):
  - Retrieval (owner-approved): BM25 uses Qdrant's IDF modifier (`qdrant_schema.sparse_vectors_config`; `ensure_sparse_idf` migrates an existing collection in place at `ensure_collection` — no re-embed, no tag bump, never a refusal). The reranker scores `documents.contextual_text` (`filename › section\ntext`), the string that is embedded; measured on the fixture corpus with jina int8, top documents unchanged and scores within 0.06, far above `rerank_min_score`. `prompting.fit_prompt_to_context_window` fits the prompt to `LLM_CONTEXT_WINDOW` (or `OLLAMA_NUM_CTX` for Ollama) — lowest-ranked sources first, never below one, then the oldest history — using a deliberately high chars/3 token estimate; dropped sources get trace drop reason `context_budget`.
  - Answer cache (`api/answer_cache.py`, `ANSWER_CACHE_SIZE`/`_TTL_SECONDS`, 0 = off): keyed on normalized question + scope (filenames, tags) + provider/model + overrides + a process-wide corpus generation that every ingest (even a failed one), delete and tag change bumps. Never used with history. `RagPipeline.answer`/`answer_stream` wrap `_answer_uncached`/`_answer_stream_uncached`; a hit replays `sources` → one `delta` → `done` with `cached: true` and the original trace id, and is counted in `docrag_answer_cache_hits_total`, not the stage histograms. `use_cache: false` (the UI's Regenerate) skips the lookup but stores the result.
  - Tags: `tags` payload field (keyword index, `DocumentChunk.tags`), `PATCH /documents/{filename}/tags` (payload-only `set_payload` under the filename lock, `normalize_tags`: ≤20, ≤40 chars, case-insensitive dedupe), `GET /documents` `tags` map, `tags` on `/questions*` (AND-ed with `filenames`). Reads settings through the app's dependency overrides.

  - SSE: `sse.with_keepalive` runs the pipeline on a thread and sends `: ping` every 15 s of silence (closing the source when the client leaves); `Cache-Control: no-cache` and `X-Accel-Buffering: no`. `/health` is `async`.
  - Provider errors: `llm._provider_failure` logs the exception and returns a fixed reason per LiteLLM exception class; `redact_url` strips credentials from any URL shown.
  - Qdrant ports bound to 127.0.0.1 in compose; optional `QDRANT_API_KEY`. `FEEDBACK_MAX_ROWS` caps feedback. `requires-python` is `>=3.12,<3.14` (see below). Version lives only in `pyproject.toml` (`api/version.py`).
  - Frontend: `utils/id.ts:newId` replaces `crypto.randomUUID` (absent over plain-HTTP LAN). `useChat` persists source text only on the last 6 turns, prunes/selects conversations by `updatedAt`, merges other tabs' writes (`storage` event), flushes on `pagehide`, keeps a per-conversation `scope` (filenames + tags), `editAndResend` forks a new conversation, `importConversation` reads a JSON export, and marks `stopped`/`cached`/`feedback` on turns (stopped turns stay out of history). Streamed deltas don't bump `updatedAt`, and the summaries array keeps its identity, so the list doesn't re-render per frame.

DocRAG — Architecture Review

Self-hostable hybrid-RAG document Q&A: FastAPI · FastEmbed · Qdrant · LiteLLM/Ollama · Streamlit. Current design is spec-complete and sound; this review proposes correctness fixes, efficiency wins, and one new orchestration seam layer. Implementation is owner-gated — this is analysis + roadmap.

1 · What DocRAG is

DocRAG answers questions about uploaded documents with grounded, cited answers. Everything required for upload, indexing, retrieval, and Q&A is local and self-hostable; hosted LLM APIs (OpenAI) are optional add-ons, never required. Two independent provider knobs: the embedding provider (default local FastEmbed) and the generation provider (default local Ollama via LiteLLM).

4 · Findings

Grouped by kind, correctness first. Each item cites file:line.

A · Correctness

A1 — Blocking work on the async event loop critical

upload_document is async def (api/main.py:72) but after await file.read() it runs parse_document_bytes, chunk_sections, embed_texts (FastEmbed, CPU-heavy) and ingest_chunks (upsert(wait=True)) — all synchronous. A single upload stalls the whole server for every other client.

Fix: offload with run_in_threadpool (or make the handler plain def, as answer_question already correctly is).

A2 — Bare except Exception hides real errors critical

api/retrieval.py:59-62 falls back from server-side hybrid to manual RRF on any exception — masking config errors, bugs, and Qdrant outages behind a silent second path.

Fix: catch only the specific "server-side hybrid unsupported" case; let real errors surface.

A3 — Orphaned points on re-ingest correctness

chunk_id embeds a content hash, so an edited re-upload writes new points and leaves the old ones behind (api/ingestion.py:82). The index accumulates stale content.

Fix: delete-by-filename filter before upserting a document's chunks.

A4 — Embedding tag covers dense only correctness

Tag = fastembed:BAAI/bge-small-en-v1.5 (settings.py:22). Swapping the sparse BM25 model changes stored vectors but does not trip the mismatch refusal.

Fix: fold the sparse model into the tag. Do not tag the reranker — it runs at query time on already-retrieved candidates, stores nothing, so it never invalidates the index.

A5 — Sources not verified against the answer correctness

All context chunks are returned as citations regardless of whether the model actually referenced [n] (api/generation.py:163 → main.py:119). Users see "sources" the answer never used.

Fix: parse [n] markers from the answer text; return only cited sources.

A6 — Embedding-tag round-trip verified — not a bug

Metadata round-trips correctly on a real QdrantClient(":memory:"): tests/test_qdrant_schema.py asserts the tag reads back and passes; qdrant-client 1.18 accepts create_collection(metadata=…). Only open item: validate parity against a live server-mode Qdrant (payload indexes already warn they are no-ops locally).

B · Efficiency

B1 — ensure_collection on every request efficiency

Called from both ingestion.py:43 and retrieval.py:56 — an extra collection_exists/get_collection Qdrant round-trip on every upload and query.

Fix: cache the collection-ready + schema-validated state (bust on re-ingest).

B2 — Sync LLM, no streaming, no timeout efficiency

litellm.completion (generation.py:66). First token is fully buffered, and a hung Ollama blocks the request indefinitely — no request_timeout is passed.

Fix: add request_timeout; adopt acompletion + streaming for first-token latency.

B3 — Dense & sparse embed sequentially minor

Two sequential model passes over the text list (embeddings.py:76-83). Both CPU-bound, so parallelizing yields limited gain — noted for completeness.

B4 — Whitespace "token" chunking limitation

text.split() words ≠ the embedding model's real token budget (documents.py:106), so 500-"token" chunks can overflow or underflow the model window. Real-tokenizer fix is out of the chosen scope; flagged as a known limitation.

5 · Proposed architecture — AFTER

Introduce three seams so handlers depend on one interface each, Qdrant is hidden behind a repository, and blocking ingest work is offloaded. Existing Protocol injection points (EmbeddingProvider, Reranker, ChatGenerator) are kept.

6 · Seams & signatures

Proposed interfaces next to the current loose functions they compose. Signatures are illustrative (owner-gated implementation).

New orchestration seams

class VectorRepository(Protocol):
    def ensure_ready(self) -> None: ...                      # cached; replaces per-request ensure_collection
    def hybrid_search(self, emb: EmbeddedText) -> list[RetrievedChunk]: ...
    def upsert(self, points: Sequence[PointStruct]) -> int: ...
    def delete_by_filename(self, filename: str) -> None: ...  # fixes A3 orphans

class RagPipeline:
    def __init__(self, repo: VectorRepository, embedder: QueryEmbeddingProvider,
                 reranker: Reranker, generator: ChatGenerator, settings: AppSettings) -> None: ...
    def answer(self, question: str) -> QuestionResponse: ...  # retrieve → rerank → generate → cite+verify

class IngestService:
    def __init__(self, repo: VectorRepository, embedder: EmbeddingProvider,
                 settings: AppSettings) -> None: ...
    async def ingest(self, filename: str, content: bytes) -> IngestResult: ...  # offloaded, cleans first

Net effect: main.py handlers shrink to call one seam and shape the response; Qdrant is no longer referenced from retrieval/ingestion; the per-request round-trip disappears.

7 · Phased roadmap

Ordered by risk / value. Each phase is independently shippable. Implementation stays gated behind owner approval per CLAUDE.md.

  1. Phase 1 — Correctness do first
    A1 unblock ingest (threadpool), A2 narrow the retrieval except, A3 delete-by-filename, A4 sparse in tag, A5 citation verification.
    Touches: main.py, retrieval.py, ingestion.py, settings.py, generation.py. Low risk, high value. Existing tests mostly hold; add tests for cleanup + citation filtering.
  2. Phase 2 — Efficiency next
    B1 cache collection-ready, B2 LLM timeout + streaming.
    Touches: qdrant_schema.py/repo, generation.py, ui (stream rendering optional). Medium risk (streaming changes response shape).
  3. Phase 3 — Seam refactor structural
    Introduce VectorRepository, RagPipeline, IngestService; thin the handlers; wire via dependencies.py lru_cache singletons.
    Touches: new api/pipeline.py, api/repository.py, main.py, dependencies.py. Larger diff but mostly mechanical; absorbs Phase 1–2 fixes cleanly and makes both paths testable without in-memory-client gymnastics.
